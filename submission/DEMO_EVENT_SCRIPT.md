# RRFLOW — three-minute event demonstration

**Story:** Give context a place. Give a decision a reason. Give the next attempt the evidence from the last one.

**Deliverable:** 180-second silent, captioned landscape film, primarily actual screen recordings. Use the generated concept intro for the opening eight seconds only. The public walkthrough uses curated data; the owner-workspace segment shows the Shippin brain and public engineering sources. Personal examples are fictional. Never record a real inbox, password, secret, private reviewer note or unrelated browser tab. The voiceover below is available to a human presenter; no synthetic narration is included without the user's voice selection.

**Two loops:**

1. A person inspects a placement suggestion, previews a different home, and explores the actual source structure behind a specialist. Public placement changes remain a preview for this visit.
2. A failed development check retains its evidence, a reviewed correction links to a later passing check, and the resulting practice becomes reusable context.

## Recording and editing instructions

- Record the actual deployment only after the public route and password boundary pass verification. Use the real runtime expiry value in the countdown; do not create a second deadline in the video or state that the event is still open after expiry.
- Capture at 1920×1080, normal playback speed. Use calm cursor movement, tight but readable framing, and two-second holds on important results. Keep request timestamps readable. Match the app’s lavender, mint, amber and charcoal palette.
- Login happens outside the recording. Never show the password, a session cookie, Infisical output, DevTools storage, or the personal inbox. For the authenticated decision, use a source already published to the public repository. If the chosen item is already confirmed, show the saved decision and refresh it; do not invent a misleading new correction for the camera.
- The public placement preview is transient. Its preview notice must remain in the shot. The protected segment is a separate, labeled graph/source read. Do not claim that this footage demonstrates a saved placement.
- The intro is conceptual generated imagery. Add any exact title as an editing overlay; never ask the model to render a working application or claim generated graphics are live product footage. Cut directly from the intro into the real UI.
- Use the actual accepted/failure states for HydraDB and Raindrop. **Accepted** does not mean indexing completed or a quality improvement was measured. The reviewed practice is stored context, not automatic model training, autonomous improvement, a promoted prompt, or a globally learned classification rule.
- No Qdrant latency or performance claims. The demo’s two loops stand on source decisions, native persistence and public development evidence.
- Caption the narration. Use subtle cuts or short dissolves; avoid simulated typewriter narration, flashing effects and decorative data counters. Keep the final end card on screen for at least three seconds.

## Alternate narration for incomplete evidence

**Raindrop delivery is pending or failed:** “The decision is saved in HydraDB. Raindrop delivery is still pending or needs attention, and the interface keeps those states separate.”

**HydraDB read is unavailable:** “The public demonstration reads its curated snapshot directly from HydraDB. This request is unavailable right now, and the app reports the failure instead of substituting invented live data.” Show a previously recorded segment only with a clear recording-date label.

**Event window already ended:** “The curated event has ended. The same demonstration is available after workspace sign-in.” Do not present an expired public link as anonymously accessible.
